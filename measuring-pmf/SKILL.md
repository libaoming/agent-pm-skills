# Agent 的 PMF

**agent 的 PMF 不看用户来不来，看活交出去之后收不收回来。**

普通产品的 PMF 问“用户离不开它吗”，靠的是用户**回来**的频率。agent 产品一旦把判断权交出去，
价值恰恰在于用户**不用回来**它也在干活，“来不来”这个信号就失效了。要看的是：
**用户有没有停止自己做这类活。**

这是 agent 产品版。通用的 PMF 方法（Sean Ellis 40% 问卷、留存曲线、自然增长）见
lenny-skills 的 `measuring-pmf`，本 skill 只讲 agent 产品上哪些要换掉、换成什么。

## 怎么帮（How to Help）

1. **先定位到岗位** —— 用 [agent-positioning](../agent-positioning/SKILL.md) 判定它是岗位还是能力包、
   翻了哪几格。能力包没有委托可言，PMF 按普通工具测，直接用 lenny-skills 的通用版。
2. **换掉失效的信号** —— 判断权交给 agent 之后，DAU、会话数、使用时长不再度量任何东西，
   从 PMF 论据里拿掉，改看“收回的活”和授权留存。判断权没翻的岗位，这些指标仍然可用。
3. **找拉力** —— 查用户有没有主动扩大它的职责、把新类型的活交给它。
4. **按岗位出结论** —— 一个产品里有几个岗位，就出几个 PMF 结论，不合成一个数。

## 核心原则（Core Principles）

### 问“停了它，你要把多少活拿回来”，不问“你会不会失望”

Sean Ellis 问卷问的是情绪（“非常失望”的比例过 40%）。agent 产品可以问得更硬：

```
如果它明天停了：
  你要把哪些活拿回来？每周大概多少小时 / 多少件？   → 这就是它替你扛着的量
  这些活你会怎么办？
    自己扛回来，或者找别的工具、雇人补上          → 真依赖
    两样都不做，就让它没人干                      → 这活本来可有可无
```

“失望”可以被新鲜感和好感撑起来；**“要收回多少活”只能被真实的委托撑起来。**

### 授权留存曲线要走平在零以上

普通产品画的是“第 N 周还有多少用户回来”。agent 产品画的是
**“第 N 周，用户交出去的授权（定时任务、事件触发任务、长期指令）还有多少真正在起作用”**。

一条授权在第 N 周算“留存”，要同时满足三条：

```
① 这一周真的运行过
② 没被用户关掉，也没被系统因为长期没人理而自动暂停
③ 这一周至少有一张回执被用户打开或据此行动过
```

第 ③ 条最容易漏。一条没人看回执的授权，只是在后台空转，用户其实已经忘了它，不能算依赖。
用户把一条授权删掉重建、改几个字，算同一条的延续，不算流失。

```
授权留存（第 N 周）= 某一周创建的授权中，第 N 周仍满足三条的数量 ÷ 该周创建的授权数
```

曲线一路掉到零 = 用户试过委托、然后收回了。这比用户流失更早暴露问题：
人还在，活已经拿回去自己做了。

授权的价值是延迟兑现的：创建当天没感觉，要等它在你不在的时候干成几次才显出作用。
所以别在头两周下结论，头两周的曲线主要反映新鲜感。经验上可以先看到第 4 到 8 周，
具体多久取决于这类授权多久运行一次。

### 拉力信号是用户主动扩大它的职责范围

通用版说：真正的 PMF 出现时，客户的问题从客气变成急切（“怎么定价、什么时候能开始”）。
agent 产品上对应的急切信号是：

```
“能不能也帮我盯一下 X？”          → 主动加新的活
“这类事以后不用问我了”            → 用户主动放松了执行前的确认（不可逆的动作除外）
“它怎么没处理 Y？”                → 默认它该管，说明已经把它当成岗位
```

第二条要小心解读：用户想少被打扰是好信号，但对外发送、花钱、删除这类**不可逆**的动作，
不管用户多信任它，执行前的确认都不该取消。

反过来，用户每次都手动发起、从不加新授权，说明它还停在“一次动作管一次执行”的省手阶段。

### 委托判断的岗位，误否率要靠抽检，不能靠用户复核

如果岗位要替用户否掉东西，要分开看三个数，不能混成一个：

```
复核率   用户打开它否掉的条目看的比例        → 用户还在不在检查它
捡回率   用户看了之后又捡回来的比例          → 用户检查时发现它否错了多少
误否率   它否掉的里面，本该要的比例          → 它实际错了多少
```

关键在于：**用户不再复核之后，误否就看不见了。** 这时复核率很低、捡回率为零，
可能是信任，也可能只是没人在看。所以误否率不能从用户行为里推，要**定期抽一小批它否掉的条目，
由人盲审**，独立算出来。

```
复核率下降，抽检的误否率也低    → 信任建立得有依据，这是判断岗位最硬的 PMF 证据
复核率下降，抽检的误否率不低    → 用户放弃检查了，不是信任，迟早出事
复核率一直很高                  → 判断权没有真正交出去，再高的使用量也不是 PMF
```

误否率的口径见 [north-star-metrics](../north-star-metrics/SKILL.md)。

### 按岗位测，不按产品测

同一个产品里，不同时长的任务属于不同岗位。一个岗位有 PMF、另一个没有，
合成一个产品级数字会互相抵消，结论两头都错。**PMF 是岗位的属性，不是产品的属性。**

### 先证明委托留得住，再优化单位成本

通用版的顺序是“先有需求，再有满意，最后才是效率”。agent 产品上对应：

```
需求   → 有人愿意交第一条授权
委托   → 授权留存曲线走平
效率   → 再去压每件活的 token 成本和延迟
```

委托留存还没走平就去压成本，等于在优化一个用户随时会收回的东西。

## 框架（Templates & Frameworks）

**PMF 信号对照表**

| | 普通产品看 | agent 产品换成 | 为什么 |
|---|---|---|---|
| 依赖 | “非常失望”比例 | 停用后要收回的活量 | 情绪可被新鲜感撑起，活量不能 |
| 留存 | 用户回访曲线 | 授权留存曲线（在跑 + 回执有人看） | 判断权翻了之后，用户不来它也在干活 |
| 拉力 | 急切的定价、实施问题 | 主动扩大职责、放松确认 | 急切在 agent 上表现为交更多活 |
| 满意 | NPS、好评 | 复核率下降 + 抽检误否率低 | 信任要有依据，不能只是不再检查 |
| 范围 | 产品级一个数 | 每个岗位一个结论 | 岗位之间会互相抵消 |

## 问用户的问题（Questions to Help Users）

- “如果它明天停了，你要把哪些活拿回来？每周多少？拿回来之后你会自己做，还是找替代？”
- “某一周创建的授权，第 8 周还有多少在跑、而且回执有人看？”
- “有没有用户主动给它加过新类型的活，或者把原来要确认的步骤改成不用确认？”
- “它否掉的东西，用户还打开看吗？你们有没有定期抽一批人工盲审？”
- “这个产品里有几个岗位？你说的 PMF 是哪一个岗位的？”

## 要指出的常见错误（Common Mistakes to Flag）

- **判断权翻了之后，还拿 DAU、会话数证明 PMF** —— 这些指标已经不再度量任何东西。
- **把头两周的使用量当依赖** —— 授权价值延迟兑现，头两周主要是新鲜感。
- **只看用户留存，不看授权留存** —— 人还在、活已收回，是最常见也最隐蔽的“假 PMF”。
- **把“授权还开着”当留存** —— 没人看回执的授权只是在空转。
- **复核率低就当成信任** —— 没有抽检的误否率撑着，可能只是用户放弃检查了。
- **全产品报一个 PMF 数** —— 岗位之间会互相抵消。

## 收口

**做完 = 每个岗位都有一句 PMF 结论，且结论能用三样东西之一支撑**：
停用后要收回、且用户会自己扛或找替代的活量；走平的授权留存曲线（按三条算）；
复核率下降且抽检误否率低。三样都拿不出来，结论就是“还不知道”，不是“有”。
