# Agent 的激活与信任爬坡

**要委托的岗位，激活时刻不是第一次对话，是它第一次在目标级上替用户跑通一件事。**

普通产品的激活是“用户第一次感受到核心价值”，比如发出第一条消息、建好第一个项目。
agent 产品要分情况：

```
秒级、分钟级的任务   用户一直盯着，价值就在当场的速度和质量
                     → 激活照通用方法定义，见 lenny-skills 的 user-onboarding-activation
小时级以上的任务     价值在于用户不在的时候它也在干活，第一次对话里根本发生不了
                     → 激活要定义在委托上，本 skill 讲的是这一类
```

通用的引导方法（30 秒见到价值、减少摩擦、用引导代替空白页）对两类都适用，
本 skill 只讲委托型岗位上要额外换掉、加上什么。

## 怎么帮（How to Help）

1. **先定目标级** —— 用 [agent-positioning](../agent-positioning/SKILL.md) 看任务时长，
   对照下面的五级梯子，定出这个岗位该爬到哪一级。
2. **定激活事件** —— 激活 = 岗位第一次在目标级上跑通，且对应的回执被用户接受。
3. **排爬坡路径** —— 从 L0 到目标级，每一级只加一样新东西，不跳级。
4. **用留存校验** —— 激活定义对不对，看达到它的用户，授权留存是不是明显更高
   （见 [measuring-pmf](../measuring-pmf/SKILL.md)）。

## 核心原则（Core Principles）

### 委托从“一次动作管一次执行”变成“一次授权管很多次执行”

```
1 次动作 = 1 次执行    → 省手。用户每次都得在场，这还是工具
1 次授权 = N 次执行    → 委托开始。用户第一次可以走开
```

中间有一个半格：定时任务、按名单跑。用户交出了**什么时候做**，但**做不做、怎么判**
还写死在规则里。半格也算爬了一步，但别把它当终点。

### 从可逆的活开始爬

第一次交出去的活，干错了要能看见、能撤回：

```
可逆（出草稿、读、整理、写内部记录）  → 干完再报，别问
不可逆（对外发送、承诺、花钱、删除）  → 停下来叫人，放到爬坡最后，而且执行前始终要用户确认
```

新用户对它的判断还没有任何校准。第一次委托就让它做不可逆的事，
一次出错就会把用户打回“什么都自己来”，而且很难再爬回来。

### 第一张回执决定有没有第二次授权

授权之后，用户人不在，**唯一的证据是回执**（它干完活后发给用户的那份结果报告）。
回执沉默，用户分不清是“没事”还是“它没跑”，只能自己回去查，委托就退回了省手。

```
① 回执要主动推给用户，不是被动存在某个页面里
② 没事也要明确写“无”，防沉默的歧义
③ 以完成物开头，不以过程开头
```

授权的价值是延迟兑现的。引导期要**尽快送出第一张回执**，比如创建授权后立刻试跑一次，
把“延迟”压到用户还在场的时候。

### 授权在人在场的时候批，并当场告诉用户怎么停它

用户创建或修改一条授权的时候，人正在场，这是批准几乎不花额外成本的时刻。
在这时让用户批准的是**一条规则**（“以后遇到这类事就这么办”），不是某一个动作，
一次批准管之后的 N 次执行。

同时当场告诉用户：**要停它，停的是哪个对象**，在哪里暂停、修改、撤销。
知道怎么撤回的人，才敢交出去。

### 用岗位模板替掉空白输入框

agent 产品的“空白页”是一个写着“你想让我做什么？”的输入框。它把最难的一步
（定义一个岗位）留给了最不懂的人。给**预填好的岗位模板**：做什么、不做什么、
多久汇报一次、什么情况立刻叫你。用户改几个字就能交出第一条授权。

### 判断交出去之前，它得先记得住用户的纠正

让它替用户否掉东西（判断委托），前提是用户纠正过它一次，**下次它就不会再犯同样的错**。
记不住纠正的 agent，同一个错会犯一百遍，用户只能一直盯着，判断权交不出去。

所以判断委托这一级要同时满足两条：

```
① 它否掉的条目和理由，用户看得见、能核对
② 用户的纠正会被记下来，影响它下一次的判断
```

用户核对几轮、发现它否得对、纠正也生效了，才会停止复核。

### 不是每个岗位都该爬到顶

爬坡的终点由岗位决定，不是越高越好：

```
主要价值是“一直在”（接待、答疑、值守）   → 停在 L2。判断权越窄越安全
主要价值是“替你决定”（筛选、分诊、审核） → 才需要爬到 L3
要替你对外发送、花钱                     → 才需要 L4，且不可逆的那一步始终要确认
```

## 框架（Templates & Frameworks）

**五级信任爬坡**

```
L0 当场协作     1 次动作 = 1 次执行            用户一直盯着
L1 可逆委托     交出一件可逆的活，干完再报      用户当天回来看结果
L2 定时或事件委托 授权 + 自动运行 + 回执         用户长期不在，靠回执知情
L3 判断委托     它可以否；否掉的可见；纠正记得住  用户停止复核
L4 不可逆动作   对外发送、花钱，执行前确认       用户只批关键一步
```

**按任务时长对应目标级**（时长的判断见 [agent-positioning](../agent-positioning/SKILL.md)）：

| 任务时长 | 用户状态 | 目标级 | 激活事件 |
|---|---|---|---|
| 秒级、分钟级 | 一直盯着 | L0 | 照通用方法：第一次当场完成核心任务 |
| 小时级 | 当天回来 | L1 | 第一件可逆的活干完，结果被接受 |
| 天级、周级 | 长期不在 | L2，按需要再到 L3、L4 | 第一条授权自动运行，第一张回执被接受 |

“回执被接受”指：用户看了，没有关掉这条授权，也没有把活拿回来手动重做一遍。

## 问用户的问题（Questions to Help Users）

- “这个岗位的任务是多长时间的？它该爬到哪一级？”
- “用户第一次交出一条授权，平均发生在注册后多久？有多少人从来没交过？”
- “用户的第一条授权是可逆的活吗？”
- “授权创建后，第一张回执多久送到？没事的时候它会说‘无’吗？”
- “用户知道要停它的话，该去哪里、停哪个对象吗？”
- “它否掉的东西，用户看得见吗？用户纠正它之后，下次还会犯同样的错吗？”

## 要指出的常见错误（Common Mistakes to Flag）

- **所有岗位用同一个激活定义** —— 短任务不需要委托，拿授权去衡量它，激活率会被算成零。
- **把注册或第一条消息当委托型岗位的激活** —— 第一次对话发生不了委托。
- **一上来就要用户授权不可逆的动作** —— 一次出错，信任很难爬回来。
- **回执沉默** —— 用户分不清“没事”和“没跑”，只能自己回去查。
- **给一个空白输入框** —— 把定义岗位这件最难的事留给新用户。
- **记不住纠正就开放判断委托** —— 同一个错反复犯，用户只能一直盯着。
- **把所有岗位都往 L4 推** —— 以“一直在”为价值的岗位，判断权越窄越安全。
