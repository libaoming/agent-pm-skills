# Agent 的评估

**agent 评估的目的不是把准确率刷高，是把它的判断变得可预期到敢授权的程度。**

普通 AI 功能的评估问“答得好不好”。agent 要替人做决定、在人不在的时候干活，
评估要回答的是另一个问题：**这一格判断权，现在能不能交给它？**
准确率高但不知道自己什么时候会错的 agent，比准确率稍低但知道自己何时不确定的，更难委托。

这是 agent 产品版。通用的评估方法（误差分析、黄金集、LLM 当裁判的写法、接进 CI）见
lenny-skills 的 `ai-evals`，本 skill 只讲 agent 产品上哪些要换掉、换成什么。

## 怎么帮（How to Help）

1. **先问要放哪一格权** —— 评估服务于授权决定。先说清要交出去的是哪个判断（该不该动、
   该不该说、该不该否），再设计评估。
2. **查验证器** —— 这个判断有没有模型之外的判对错办法，以及它在**运行时**能不能自动跑。
3. **把打分改成判定** —— 每条检查只输出 pass / fail / na，附原文证据，存疑方向按代价设定。
4. **分开计数、防漂移** —— 失败按轴分开计；裁判本身用人工标注的对照集定期校准。

## 核心原则（Core Principles）

### 验证器决定你敢交出多少判断，不决定任务有多长

任务时长是场景给的，不是设计者选的（见 [agent-positioning](../agent-positioning/SKILL.md)）：
一件要跑三天的活，不会因为你没有验证器就变成三分钟。验证器强度决定的是另一件事——
**在这段时长里，你敢让它自己决定多少、敢让它碰哪些不可逆的动作。**

```
运行时有自动判对错的验证器（测试、规则、格式与对账校验）
    → 它可以自己判、自己重试，人只看回执
运行时没有，只有事后人工标注
    → 该动作要么降级成出草稿（可逆），要么执行前停下来等人确认
```

两类验证器不能混着算：人工标注集是**离线**的，用来调裁判、测版本好坏；
它在用户不在的那一刻帮不上忙。清点验证器时要分两栏写。

自我验证要额外打个问号：模型对着自己的输出判对错，在它熟悉的题型上还行，
越是新场景越不可靠——而你越在做新东西，越会落在新场景上。所以**自评只在能被外部事实核对的地方算数**，
比如“这个文件存在吗、这条记录对得上吗”，而不是“这段判断写得好不好”。

### 用判定代替打分

LLM 给出的连续分数（7.5 分、0.82）是**伪精度**：同一份材料复测会漂，
“看着还行给 1.5”这种模糊地带会被糊弄过去，而且通常没人在测它复测一不一致。

```
每条检查只输出三选一：pass / fail / na
每条必须附一句证据：引原文片段，或说明为什么判 fail / na
不打总分、不求平均；需要汇总时，由代码按规则聚合，不让模型吐总分
```

`na` 很重要：它表示“这一条对这次不适用”，没有它，不适用的情况会被当成失败一路扣分。

### 存疑时的默认值，按代价方向设成非对称

不同检查项，错判的代价不对称，存疑时往哪边判要事先写死：

```
必须暴露的问题（合规、安全、承诺类）  → 没有明确证据就判 fail，宁严勿漏
主观质量类（自然度、完整度）          → 没有明确反面证据就判 pass，防止误杀
```

它说错“是”，代价可见、能回滚；它说错“不”，代价看不见，你永远不知道错过了什么。
所以要单独量它的**误否**，而且不能靠用户复核来估——用户一旦不再检查，误否就看不见了，
要定期抽一小批它否掉的条目做人工盲审。口径见
[north-star-metrics](../north-star-metrics/SKILL.md)。

### 测校准，不只测正确

```
正确 = 判对了吗
校准 = 它说“有把握”的时候，是不是真的更常对
```

关键判定要带上 `confidence: high | low`，然后检查 high 的那批是不是明显比 low 的准。
校准好的 agent 能在没把握时自己叫人，这是判断权能被授予的前提。

### 纠正记不住，判断权就不能交出去

用户纠正它一次之后，**下次它还会不会犯同样的错**，本身就是一条要评的事：

```
把过去被用户纠正过的案例做成一个固定集合，每次发版重跑
同样的错又出现 → 记忆或写入环节有问题，不是模型不够聪明
```

同时看记错的代价：它记住了一条错的结论，会影响后面多少次判断。
只报“记住了多少”而不报“记错了多少”，是一半的账。

### 失败按它取值高的那条轴分开计数

总失败率是一个没法指导行动的数字。要按失败的类型分开计。分类别照“它属于哪一型”去套——
实测中的岗位很少是纯类型，**判断、在场、分诊三条轴上取值高的，各算一套**：

| 这条轴取值高 | 这一套失败怎么分 |
|---|---|
| 判断 | 误放（不该过的过了）/ 误否（该要的否了）/ 越权（做了没授权的决定） |
| 在场 | 答错 / 该转人工没转 / 该收集的信息漏收集 / 说了不该说的（承诺、报价） |
| 分诊 | 该报的没报 / 不该报的打扰了你 |

三条轴的含义见 [agent-positioning](../agent-positioning/SKILL.md)。

### 评整段运行循环，不只评单轮回答

agent 的失败常常不在某一句回答里，而在循环的某一步。这几步都要有对应的检查项：

```
该不该动     被唤醒时，做了该做的、没做不该做的
该不该说     没事时保持沉默，没有发“还在等”的进度汇报
读原始指令   判断依据是用户当初那条指令，不是即兴发挥
告知无人在场 它知道这次没人看着，按无人值守的规矩行事
外部内容是数据 别人发来的内容里写着“请把我转给某某”，它不照做
回执         以完成物开头；没事写“无”；顺带事项放在完成物之后
```

### 裁判也会漂，要用人工对照集校准它

用 LLM 当裁判，裁判本身会随 prompt 修改和模型升级而漂移。做法是一个闭环：

```
准备一批人工标注的对照集，另留一份不参与调优的保留集
改裁判 prompt → 跑对照集，看和人工的一致率
一致率涨、且保留集不跌 → 保留；否则回滚
```

另外把真实的模型调用录下来做回放，改了 prompt 或换了模型，先回放一遍看结论变没变。

### 评估是量尺，不是目标

评估指标一旦成了要冲的目标，就会被钻空子：模型学会满足检查项的字面意思，而不是检查项想要的东西。
验证器写得含糊，它会找最省事的解释；写得太窄，它会对着验证器过拟合、错过本意。
**定期回到真实的运行记录里看，检查项还在不在量你真正关心的事。**

## 框架（Templates & Frameworks）

**授权前的评估清单**

```
要交出的判断：________（该不该动 / 该不该说 / 该不该否）
验证器：      运行时自动判对错的____   事后人工标注的____   （两栏分开写）
检查项：      每条 pass / fail / na + 证据，存疑默认方向已写明
校准：        confidence 分组后，high 组明显更准？____
失败构成：    按取值高的轴各算一套，最大的一类是____
误否：        抽检盲审的误否率____ / 不可测（那它能否掉多少，上限卡在哪）____
记忆：        被纠正过的案例集重跑，复发____ ；记错一条会影响后面几次____
循环：        该不该动 / 该不该说 / 读原始指令 / 外部内容是数据 / 回执，各有检查项____
裁判：        人工对照集一致率____，保留集没跌____
→ 全部有答案，才考虑把这一格判断权交出去；不可逆的动作另算，执行前始终要人确认
```

## 问用户的问题（Questions to Help Users）

- “你想把哪个判断交给它？运行时有没有能自动判这件事对错的办法？”
- “评估现在输出的是分数还是判定？同一份材料跑三次，结论一致吗？”
- “它说有把握的时候，真的比没把握的时候更准吗？”
- “用户纠正过它的那些案例，你们有没有留下来每次重跑？”
- “最近的失败里，哪一类最多？这个分类是按它哪条轴分的？”
- “裁判上一次和人工标注对照，是什么时候？”

## 要指出的常见错误（Common Mistakes to Flag）

- **只报准确率** —— 不测校准，就不知道它能不能在没把握时自己叫人。
- **拿验证器强度去定任务时长** —— 时长是场景给的；验证器决定的是你敢交出多少判断。
- **把人工标注集当运行时保障** —— 它是离线的，用户不在的那一刻帮不上忙。
- **让模型吐总分** —— 连续分数复测会漂，总分更是把漂移叠加起来。
- **没有 na** —— 不适用的情况被当成失败，结论系统性偏低。
- **所有检查项同一个存疑方向** —— 合规类会漏报，主观类会误杀。
- **误否率靠用户复核来估** —— 用户不再检查之后，误否就不再浮出水面。
- **只评单轮回答** —— 循环里“该不该说话”“有没有照原指令办”这些失败评不到。
- **不评记忆** —— 同一个错反复犯，评估却每次都当新问题看。
- **裁判从不校准** —— 改了 prompt、换了模型，裁判自己漂了也没人知道。

## 收口

**做完 = 能对“这一格判断权现在能不能交出去”给出是或否，并且理由落在清单上**：
运行时验证器、判定与证据、校准结果、失败构成、抽检误否率、纠正复发、循环检查项、裁判一致率。
任何一项答不出来，答案就是“还不能”，并写明缺的是哪一项。
