# Deep PRD 交付前清单

逐条勾。任一条不过,PRD 未完成。

## 三条判据(总闸,按优先级)

- [ ] **可转述(第一)**:合上文档,凭记忆能向外行讲清「解决什么问题 / 关键取舍 / 现在什么状态」。讲不清→§2 或 §5 不够抓人
- [ ] **决策可追**:每个影响架构的选择在 §12 有一行「为什么 + 否决的备选 + 定死/可复议」;AI 隐性做的取舍已被逆向逼出来
- [ ] **研发零推断**:没有项目背景的研发读全篇,没有任何一处要他「自己决定」

## AI 已实现时的两个专项检查

- [ ] **逆向萃取过取舍**:向 AI/代码问过「哪里做了取舍、否决了什么、为什么」,答案进了 §5/§12
- [ ] **现状锚定(as-built)**:凡写「现状/已实现」的都回读过代码/verify;passing / in_progress / 未部署诚实分开,没拿方案描述当现状

## 三方受众 + AI 必答三问(调研补足)

- [ ] **老板入口**:§0 有「不含技术词的一段话」,一句话说清价值(PR/FAQ 精神)
- [ ] **三方各有入口**:老板读 §0+§1、产品读 §1–5+§11、研发读 §6–9+§12,不是三份文档
- [ ] **AI 必答三问(做 AI 功能时)**:①模型不许做什么(禁区)②人在哪步兜底 ③怎么测校准而不只测正确——三问齐
- [ ] **成功指标**:§10 除工程 verify,还写了「上线后看什么数字判断值不值」(Doshi 补足)

## 逐段自检

- [ ] §0 使用契约:说清了谁读、怎么用、哪些能动
- [ ] §1 问题:用户故事开场(不是功能开场),点出「墙」
- [ ] §2 概念:关键实体成表;最易混的一对讲清本质区别 + 例子
- [ ] §3 流程:**两图齐**——架构图谱(静态,mermaid flowchart,进程/表/边界;安全边界=图上不存在的箭头+注)+ 数据 flow(动态,sequenceDiagram,一次请求走完全程);异步的话标清交棒点/汇合点
- [ ] §6 字段词典:逐字段「类型/含义与取值/谁写/谁读」成表,不止 DDL 注释;隔离约束能从「谁写」列直接读出
- [ ] §5 策略:每条都有「不这么做会怎样」的**具体反例**(不是泛泛而谈)
- [ ] §7 API:每端点有 请求字段/内部步骤/响应/错误码,全
- [ ] §8 落点:后端函数有签名,前端有按文件的改动表,prompt 有全文
- [ ] §10 验收:每条标层 + 可判定断言;passing 闸**含真信号**(不止本地绿)
- [ ] §11 切片:线性、每片独立可验可止损
- [ ] §12 决策表:分组;每条五列齐;状态位只用「定死/可复议」

## 两个最容易塌的地方(重点复查)

- [ ] **§5 有没有退化成「功能描述」?** 判据:每条能不能回答「为什么不走另一种做法」。不能 → 它是实现细节,移走。
- [ ] **§12 有没有漏决策?** 机械动作:回读 §3/§4/§5/§9,凡出现「选了 A 而非 B」「默认值是 X」「不做 Y」的句子,都该在决策表有对应行。

## 反模式(见到就改)

- ❌ 一上来讲方案,没讲为谁解决什么
- ❌ 术语现编现用,§2 没建词汇表
- ❌ 决策散在正文,§12 只是复述而非「拍板 + 否决的备选」
- ❌ 验收写「要有测试」而非「测什么、断言什么」
- ❌ passing 闸只有本地绿,没有真信号
- ❌ 模板段段填满但注水——求简先于求全,没每次都用到的段就删
