## 这份 PRD 的使用契约

目标 = 研发拿到即可实现,**全程无需自己做设计决策、无需推断**。会影响架构的选择本文档都已拍好默认值(§12),照做即可;标「可复议」的 owner 事后可调但**不阻塞现在开发**。三方入口:老板读本节 + §1;产品读 §1–5 + §11;研发读 §6–9 + §12。

- §1–5 = 流程卷:讲「为什么这么设计」
- §6–9 = 实现卷:讲「照着怎么写」
- §10–12 = 验收卷:讲「怎么算做完」

遇到文档没覆盖的选择,先按 §5 策略推,推不出再问 owner——不要自行发挥。

**老板视角一段话(PR/FAQ 精神,不含技术词):** {假设已上线,一句话说清:谁因此能做成什么以前做不到的事。写不出=价值没想清。}

**一页版:** {3–5 句讲清:解决谁的什么问题、核心机制、最硬的一条约束}

**现状三态(as-built,别混):** 代码落地 / 本地 verify / 已部署 / 真信号验证——各自诚实标 ✅❌,别把「写完」当「上线」。
